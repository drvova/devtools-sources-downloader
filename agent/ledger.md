- 2026-10-29 (flatten a nested subproject: count the path references BEFORE moving, and prove the move by artifact bytes): Failure pattern: the extension lived as a subproject inside the crate (`unpack-rs/extension/` with its own `package.json`, `src/`, `test/`, `dist/`), justified as "two projects, coupled both ways". The coupling was real, but the nesting cost was not: two `src/` roots, a `dist/` three levels down, and a folder that read as one project while behaving as two. Flattening it (project files up into `unpack-rs/`, sources merged into `src/` beside the `.rs` modules) turned out to need exactly THREE code changes - and the reason is the durable part: every script resolved its paths from its own location (`path.resolve(import.meta.dirname, '..')`, `__dirname/..`), so moving a script and its tree together keeps every derived path valid; only references that reach ACROSS the boundary break. So before any move, grep for the folder name in code and docs and sort the hits into "resolves relative to itself" (safe) and "reaches across" (must change). Two other seams worth naming: a toolchain that walks the whole tree will start seeing files it never saw (the formatter, scoped to the subproject, would now format the crate's `PORTING.md` and the Rust fixture JSON - scope the ignores to the new root, `tests/**`, `tests/fixtures/**`, `PORTING.md`); and Cargo does not care that foreign sources sit in `src/` as long as `Cargo.toml` declares its entry (`path = "src/lib.rs"`), so "JS in src/" is safe by contract rather than by luck. Verify a move by artifact bytes, not by "the build succeeded": md5 the built bundles and `cmp` the binary artifact against the committed one - here `dist/js/engine.wasm` differed by 0 bytes and both JS bundles matched, proving the move changed only where sources live. Corollary: an extension's Chrome ID is derived from its dist PATH, so a move changes the ID - anything already loaded from the old path must be re-loaded.
