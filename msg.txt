The console page, plus its STYLES (42 rules) and SCRIPT (34 fragments) extracted
mechanically from report.rs into inv-consts.lisp.

THE EXTRACTION TRAP, worth recording: STYLES is a plain Rust string array but
SCRIPT is RAW strings (r#"..."#). My first extractor handled only the plain form,
found 235 of SCRIPT's 8061 characters, and reported SUCCESS - a silent 97 percent
loss. The element counts in the file header (42 / 34) are what make that class of
failure visible; a length check alone would not have.

NO ORACLE exists for this function, so the gate asserts the PROPERTIES it promises
against a hostile input (title with angle brackets and an ampersand, payload
containing a closing script tag and an onerror img):

  - complete document: doctype, body, closing tag
  - the five element ids the SCRIPT looks up by name
  - a literal closing script tag inside the payload is unicode-escaped, so it
    cannot close the data tag early - the one real injection risk here
  - title and URL HTML-escaped
  - both constant blocks rendered
  - a null argument still yields a parseable page

One assertion I got WRONG and the gate caught: I first asserted exactly one
closing script tag in the document. A correct page has two - the data block and
the script block. The property that matters is that closes never outnumber opens,
which catches an unescaped payload close while tolerating both blocks.
